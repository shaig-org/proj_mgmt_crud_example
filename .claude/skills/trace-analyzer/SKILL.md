# trace-analyzer

pytest-tracer captures per-test coverage + call traces for tests marked with
`@pytest.mark.scenario`. The `trace` Rust CLI queries the resulting `.trace-index`.

## Binary + index location

- CLI binary: `/Users/shai/proj/shaig/learn/agent_tracer/projects/trace_analyzer/target/release/trace`
- Index: `backend/.trace-index` (run all `trace` commands from `backend/`)

Alias for convenience:

```bash
alias trace=/Users/shai/proj/shaig/learn/agent_tracer/projects/trace_analyzer/target/release/trace
```

All examples below assume `cd backend` and use `--index .trace-index`.

## Text outputs only — agents cannot read PNG/SVG

Use `folded`, `mermaid`, and JSON outputs. `png`/`html`/`svg` are for humans.

## Common queries

```bash
# Find scenarios covering a file (or a specific line)
trace affected project_management_crud_example/routers/auth_api.py --index .trace-index
trace affected project_management_crud_example/routers/auth_api.py:42 --index .trace-index

# Prefer --functions-only (gives function names instead of just line numbers)
# or --with-snippets (embeds the source lines so you skip a follow-up file read)
trace affected <path> --functions-only --index .trace-index
trace affected <path> --with-snippets  --index .trace-index

# Get coverage for a scenario (JSON: scenario metadata + covered files/lines)
trace context "<scenario-id>" --index .trace-index

# Call chain for a scenario — start with `summary`, drop to `folded-compact` if needed
trace flamegraph "<scenario-id>" --format summary        --index .trace-index
trace flamegraph "<scenario-id>" --format folded-compact --index .trace-index
trace flamegraph "<scenario-id>" --format mermaid        --index .trace-index

# Discovery
trace list --index .trace-index
trace list --behavior authentication --index .trace-index
trace list --errors --index .trace-index
trace search "login" --index .trace-index
```

## Flame-graph anchoring & filtering

By default, flame-graph output **auto-anchors at the scenario's test function**
— fixture setup above the test body is trimmed, and reported depths are
relative to the anchor (anchor = depth 0). For this repo that cuts 49 fixture
frames out of 68 and leaves a clean 19-frame scenario view.

Controls:

- `--from <pattern>` — override the anchor (e.g. `--from auth_api.login` to
  zoom into just the login call tree).
- `--include-fixtures` — disable anchoring, show the full raw stack.
- `--max-depth N` — cap output at `anchor + N` frames (depth is anchor-relative,
  so `--max-depth 0` returns just the anchor, `--max-depth 3` returns 4 levels).
- `--skip <pattern>` — **prefer this over `--exclude`** for infrastructure
  noise. Removes matching frames and reparents their children, so a frame like
  `conftest.client.<locals>.override_get_db_session` (the FastAPI DI wrapper
  that sits on every stack in this repo) can be hidden without losing the app
  code beneath it.
- `--exclude <pattern>` — drop any stack **containing** a matching frame.
  Stricter than `--skip`; one matching frame kills the whole stack. Use only
  when you genuinely want to filter out entire call paths.
- `--include <pattern>` — keep only stacks containing a matching frame.

All four pattern flags accept repetition (`--skip a --skip b`) or
comma-separated values (`--skip 'a,b'`). Patterns: `foo*` prefix, `*foo`
suffix, `foo` substring.

Recommended starting incantation for this repo:

```bash
trace flamegraph "<scenario-id>" --format summary \
  --skip 'conftest*,database.Database.get_session' \
  --index .trace-index
```

## Typical workflow

1. Before editing backend code: `trace affected <path>` to find scenarios that cover it.
2. To understand one scenario: `trace context <id>` then `trace flamegraph <id> --format folded`.
3. For a cross-file call picture: `trace flamegraph <id> --format mermaid`.

## Marking new tests

```python
import pytest

@pytest.mark.scenario
@pytest.mark.behavior("authentication")  # optional tag
@pytest.mark.error                       # optional — error-path scenario
def test_login_wrong_password(...):
    """First docstring line is the searchable description."""
```

Markers are registered in `backend/pytest.ini` — do not remove them.

## Generated artifacts

All four files live under `backend/` and are gitignored (regenerated by the
rebuild pipeline below):

| Path | Produced by | What it is |
|---|---|---|
| `backend/.coverage` | `pytest --cov-context=test` | Per-test SQLite coverage DB |
| `backend/scenarios.json` | `pytest-tracer collect` | Scenario metadata (id, docstring, behaviors, outcome) |
| `backend/call_traces.json` | `pytest-tracer trace` | Per-test `sys.monitoring` call events |
| `backend/.trace-index/` | `trace build` | The queryable index (`index.db` inside) |

Flame-graph image outputs (`png`/`svg`/`html`) are not written to disk by
default — they stream to stdout. Redirect to a file if you want to keep one.

## Rebuilding the index (after adding/modifying scenario tests)

**Easiest**: run `backend/devtools/build_trace_artifacts.sh`. It runs the four
commands below AND writes per-scenario human-viewable artifacts (summary,
folded-compact, mermaid, flame PNG, flame HTML) into `backend/.trace-artifacts/`.

To run the steps manually, from `backend/`:

```bash
uv run pytest --cov=project_management_crud_example --cov-context=test
uv run pytest-tracer collect . -o scenarios.json
uv run pytest-tracer trace . -o call_traces.json
/Users/shai/proj/shaig/learn/agent_tracer/projects/trace_analyzer/target/release/trace \
    build --coverage .coverage --scenarios scenarios.json \
    --call-traces call_traces.json --output .trace-index
```

The first pytest run covers the whole test suite; to build the index you only
need scenario-marked tests to have executed with `--cov-context=test`. `.coverage`,
`scenarios.json`, `call_traces.json`, and `.trace-index/` are gitignored.

## Folded stacks format (for reading call chains)

```
module_a.func_outer 1
module_a.func_outer;module_b.func_inner 1
```

Semicolons separate frames outermost → innermost; trailing int is sample count.
